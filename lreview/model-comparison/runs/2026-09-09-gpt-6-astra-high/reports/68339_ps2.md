## Findings

### 1. `lustre/llite/vvp_io.c` (line 1579)

(defect) Could the page lock protect this invalidation and removal from ec_page_list? After cl_page_disown(), this clears Uptodate while cp_batch is still linked. A concurrent ordinary CIT_READ can now enter ll_readpage() -> ll_io_read_page() -> cl_page_list_add() before the next statement removes the page, hitting LASSERT(list_empty(&page->cp_batch)). Those readers never check CP_EC_RECOVERY, so the flag being set does not exclude them.

This is reachable when reconstruction follows a BRW read failure on a live OST: the DLM read lock can still be held, and another reader can acquire a compatible read lock. lli_trunc_sem is also held for read on both paths. The parent left the recovered page Uptodate during list removal and did not expose this requeue window.

### 2. `lustre/lov/lov_io.c` (line 2026)

(style) This is not a functional bug by itself, but could the new page unlock/reference handling go through a CLIO helper implemented in llite? Calling unlock_page() and put_page() here extends direct VM page manipulation in LOV; the client layering convention keeps these operations in llite.
