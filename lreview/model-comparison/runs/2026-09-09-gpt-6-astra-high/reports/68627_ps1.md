## Findings

### 1. `Documentation/man1/lfs-setstripe.1` (line 329)

(minor) Could this say that unaligned decimal sizes are refused? For example, 1024MB is 1024000000 bytes, exactly 15625 * 65536, so `-E 1024MB -S 64K` passes both the component-end mask in lfs_setstripe_internal() and the stripe-size alignment check. Decimal suffixes themselves are accepted.

### 2. `lustre/utils/liblustreapi.c` (line 270)

(minor) Could the changed public llapi_parse_size() contract also be documented in a man3 page and added to Documentation/man3/Makefile.am? There is currently no API manual entry for it. The new decimal suffixes and stricter suffix validation affect library consumers as well as lfs; the command manuals do not document size_units or bytes_spec for those callers.

### 3. `lustre/utils/lhsmtool_posix.c` (line 231)

(minor) Could the usage text explain that MB/GB now select decimal units while M/G and MiB/GiB remain binary? Changing the default label to MiB documents unsuffixed arguments, but leaves the changed meaning of explicit suffixes undisclosed for both -b and -c.
