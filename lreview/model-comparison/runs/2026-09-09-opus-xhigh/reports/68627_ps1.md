# 68627 ps1 — LU-20689 utils: Support decimal (SI) size units

- **Change:** https://review.whamcloud.com/c/fs/lustre-release/+/68627 (patchset 1, `c756d1ed0844`)
- **Review:** 3 finding(s), severity **low**
- **Run:** opus, 7.7M tokens, $7.55, 17m05s

## Overall assessment

Mostly good, comments inline. The parsing rewrite itself checks out: scaling the fraction one digit at a time from the last is exactly floor(frac * unit / 10^n) (nested floor division collapses), no intermediate exceeds 10 * unit, and the final `*size > (ULLONG_MAX - part) / *size_units` test is tight in both directions.

One whole-patch question. For layout sizes the new meaning of "1MB" fails loudly, but `lfs find --size 100MB` and `lfs setquota -B 1TB` keep working and quietly mean something ~7% different than they did on 2.17.57 - a script that has been setting a 1TB quota for years now sets a smaller one with no diagnostic. The man pages describe the decimal rule as if it had always held. Should they carry a version marker on it, the way lfs-setstripe.1 already writes "(since Lustre 2.15)" for pool inheritance?

## Findings

### 1. `Documentation/man1/lfs-setstripe.1` (line 329)

(minor) "a decimal unit is refused here as well" is broader than what the code does. The check is `lsa.lsa_comp_end & (LOV_MIN_STRIPE_SIZE - 1)`, and 1024MB is 1024 * 10^6 = 2^16 * 15625, so `-E 1024MB` is 64KiB-aligned and accepted (so are 2048MB, 1024GB, ...). Only decimal values that happen not to be 64KiB multiples are refused.

The -S wording above has the same shape, though it is at least tied to the 1MB example. Maybe say a decimal unit is unlikely to land on a 64KiB boundary, rather than that it is refused?

### 2. `Documentation/man1/lfs-find.1` (line 806)

(minor) On this page a bare B is not a decimal marker. `lfs find --size 1B` still takes the `case 'b'` branch in llapi_parse_size(), which sets `*size_units = 1 << 9`, so it means 512 bytes, not 1 - and this is the one page where that suffix is documented behavior for find(1) compatibility.

Worth saying the trailing B applies after a K/M/G/T/P/E letter, so a reader doesn't try `--size 1000B` and get 512000.

### 3. `lustre/utils/liblustreapi.c` (line 291)

(minor) `argbuf` is now just an alias for `optarg` - the old `argbuf = end + 1` reassignment is gone, so this is the only use left. `strtoull(optarg, &end, 0)` takes a `const char *` directly, so the variable and its cast can go.

Same line below: `end` cannot be NULL after strtoull() stored through `&end`, so the `end != NULL &&` half of the next test is dead.
