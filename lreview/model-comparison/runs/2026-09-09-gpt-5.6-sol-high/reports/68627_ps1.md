## Overall assessment

Some concerns, see inline comments.

## Findings

### 1. `lustre/utils/liblustreapi.c` (line 354)

(defect) Can the fraction be scaled without multiplying a digit by the caller-supplied unit? `size_units` is part of the exported API and has no stated upper bound; with `size_units = 1ULL << 63`, parsing `.5` wraps `5 * size_units` and returns 922337203685477580 instead of 4611686018427387904 with success. Staying below ten times the unit does not ensure that the intermediate fits in `unsigned long long`.

### 2. `Documentation/man1/lfs-setstripe.1` (line 329)

(minor) This says decimal units are refused, but the implementation only refuses an unaligned byte result: `8.192MB` parses to 8,192,000 bytes (125 * 64KiB) and passes the alignment check. Could this say that unaligned decimal values such as `1MB` are refused?

### 3. `lustre/tests/sanity.sh` (line 38187)

(style) This isn't a bug, but new quota tests should invoke `$LFS quota` directly instead of adding uses of the deprecated `getquota` wrapper. Could these three lookups use `$LFS quota`?
